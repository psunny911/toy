# 1·2·3·5초 브이로그 — 기능 명세 · 기술 검토 (v0.3, 웹 MVP)

## 1. 요구사항

1. 한 번에 **1초·2초·3초·5초** 중 고른 길이로 녹화한다 (기본 3초).
2. 녹화한 클립들을 **단순히 이어 붙여** 영상 하나로 만든다.
3. 영상에 **촬영시각**이 찍힌다.
4. 영상 **가운데에 텍스트**를 넣을 수 있다 (줄바꿈 가능, 최대 3줄).
5. 촬영시각 방향을 **가로/세로** 중에 고른다.
6. 클립을 **하나씩** 저장할 수 있고, 합친 영상은 버튼 하나로 **갤러리**에 저장한다.

## 2. 검토 결론: 웹앱으로 가능

서버 없이 브라우저 기본 API만으로 모두 된다 (외부 라이브러리 0개).

| 요구 | 쓰는 API | 지원 |
| --- | --- | --- |
| 카메라·마이크 | `getUserMedia` | Chrome/Android, iOS Safari 14.3+ (https 필수) |
| 1/2/3/5초 녹화 | `MediaRecorder` + 고른 길이 뒤 `stop()` | Chrome 49+, Safari 14.1+ |
| 클립 보관 | IndexedDB (Blob) | 전부 |
| 시각·문구 합성 | Canvas 2D | 전부 |
| 이어 붙이기 | 캔버스 `captureStream()` + Web Audio + `MediaRecorder` 재녹화 | Chrome, Safari 15+ |
| 저장·공유 | `<a download>`, Web Share(파일) | 공유는 모바일 위주 |

### 이어 붙이기 방식 비교

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| **캔버스 재녹화** (채택) | 의존성 없음, 시각·문구를 그리면서 동시에 합성 | 영상 길이만큼 걸림(1분 영상 = 약 1분), 약간의 재인코딩 화질 손실 | MVP에 적합 |
| ffmpeg.wasm | 빠른 이어 붙이기(코덱 같으면 재인코딩 없이), 포맷 자유 | 코어 ~30MB 다운로드, 텍스트 합성은 결국 재인코딩, 모바일 메모리 부담 | 나중 옵션 |
| WebCodecs + mp4 muxer | 가장 빠름, 화질 제어 | 디먹서/먹서 라이브러리 필요, iOS 지원이 최근 | 나중 옵션 |

### 시각·문구를 언제 찍나

원본 클립은 **깨끗하게** 저장하고, 촬영시각(녹화 시작 시점)과 문구는 메타데이터로 보관했다가
**합칠 때** 영상 위에 그린다. 그래서 촬영 후에도 문구를 고칠 수 있다. 미리보기 오버레이와
결과물은 같은 그리기 함수(`overlay.js`)를 쓰고 글자 크기를 화면 짧은 변에 비례시켜서
보이는 그대로 나온다.

## 3. 화면

- **촬영**: 카메라 미리보기(영상 비율 그대로) 위에 현재 시각과 입력한 문구가 실시간으로 보인다.
  길이(1초/2초/3초/5초, 기본 3초)와 시각 방향(가로/세로) 토글은 이 기기에 기억된다(localStorage).
  녹화 버튼을 누르면 진행 링 + REC 카운트다운 후 자동 정지. 전면/후면 전환(전면은 미리보기만 좌우 반전).
  녹화 중에는 시각이 녹화 시작 시각으로 고정된다.
- **클립 목록**: 가로 스크롤 카드(썸네일, 순번, 촬영시각, 문구). 누르면 편집 시트.
- **클립 편집**: 반복 재생 + 오버레이 미리보기, 문구 수정, 앞/뒤로 순서 이동, 이 클립 저장, 삭제.
  "이 클립 저장"은 그 클립 하나에 시각·문구를 입혀 내보낸다(파일명은 그 클립의 촬영시각).
- **영상 만들기**: 진행률 표시(실시간 합성 중 화면 꺼짐 방지 Wake Lock), 완성 후 재생 + "갤러리에 저장".

### 갤러리에 저장

웹은 사진 앱에 직접 쓸 수 없어서 플랫폼별로 갈 수 있는 가장 가까운 길을 쓴다.

| 기기 | 동작 |
| --- | --- |
| iPhone/iPad (Safari) | 공유 창을 연다 → "동영상 저장"을 누르면 사진 앱에 저장 |
| Android (Chrome) / PC | 파일 다운로드 → 다운로드 폴더, 갤러리 앱에 바로 보인다. 공유 버튼도 따로 있다 |

## 4. 출력

- 해상도: 첫 클립 비율, 긴 변 최대 1280px. 비율이 다른 클립은 검은 여백(레터박스)으로 맞춘다.
- 포맷: mp4 우선(iOS Safari·최신 Chrome), 안 되면 webm. 파일명 `vlog-YYYYMMDD-HHmm.mp4`
- 촬영시각: `2026.10.11 14:32`, 오렌지 글로우(캠코더 날짜 스탬프 느낌).
  가로 = 오른쪽 아래, 세로 = 왼쪽 가장자리를 따라 아래에서 위로 읽히게 90° 회전
- 문구: 가운데, 흰색 굵은 글씨 + 그림자, 최대 60자·3줄. 직접 넣은 줄바꿈은 그대로, 긴 줄은 자동 줄바꿈(3줄 넘치면 …)

## 5. 데이터

```json
{ "id": "…", "blob": "<Blob>", "type": "video/mp4", "thumb": "<Blob jpeg>",
  "recordedAt": 1791700000000, "duration": 3, "width": 1280, "height": 720,
  "text": "카페 도착\n라떼 맛집", "order": 0 }
```

- 이 기기의 IndexedDB에만 저장. 서버·계정·외부 요청 없음. 새로고침해도 클립이 남는다.

## 6. 알려진 제약 / 다음 단계

- 합치는 동안 화면을 켜 두고 앱을 띄워 둬야 한다(백그라운드에선 브라우저가 렌더링을 멈춤).
- Chrome이 webm으로 녹화하는 환경에서는 결과 파일에 길이 정보가 빠져 일부 플레이어에서 탐색이 안 될 수 있다(mp4면 해당 없음).
- iOS Safari 실기기 확인 필요(캔버스 captureStream + Web Audio 조합).
- 시각 방향은 앱 전체 설정이라 합칠 때 모든 클립에 같이 적용된다.
- 후보: 문구 위치/색 선택, 클립 사이 전환 효과, BGM, ffmpeg.wasm/WebCodecs로 빠른 합치기, PWA 설치.
